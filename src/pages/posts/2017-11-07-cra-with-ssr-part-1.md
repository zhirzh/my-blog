> This article is now part of a much longer series of posts titled [Making CRA apps work with SSR](https://hackernoon.com/making-cra-apps-work-with-ssr-b45f7c23d8db). You can find the the code [here on github](https://github.com/zhirzh/cra-with-ssr).

In the React ecosystem, [_create-react-app_](https://github.com/facebookincubator/create-react-app/) is a well-known project. It's a super useful tool that provides a zero-configuration starting point for a React app, packaged with [a lot of good stuff](https://github.com/facebookincubator/create-react-app/blob/master/packages/react-scripts/template/README.md#table-of-contents).

SSR is not one of them.

At first, implementing SSR seems rather simple. But things get complicated in the process faster than I thought. And most of the existing solutions (that I came across) are _inadequate_.

## Inadequate Implementations

### 1. Static Serving

People out there who mislabel static serving as SSR are abundant. You may come across solutions that use a server to respond with the static build files. Sometimes those generated by [react-scripts/build](https://github.com/facebookincubator/create-react-app/blob/dc95d18c9ccbf69ccc2e85b11de638f6462d7181/README.md#npm-run-build-or-yarn-build).

```js
const app = express()

app.get('/', (req, res) => {
  res.sendFile('/some/path/index.html')
})
```

This is not SSR. Simply serving the HTML file is not SSR.

### `2. babel-register`

There are many other solutions that use [_babel-register_](https://babeljs.io/docs/usage/babel-register/), which is not good.

> babel-register is apparently a bad idea for production, but, for the most part its fine ...  
>  - [Ben Lu](https://hackernoon.com/server-side-rendering-with-create-react-app-1faf5a9d1eff)

While it does make our lives easier (as you will see), it is advisable to not use in production mode. Below I list some of the projects that I found that use _babel-register_.

1. [cra-ssr](https://github.com/cereallarceny/cra-ssr)
2. [create-react-app-ssr-pwa](https://github.com/agungsb/create-react-app-ssr-pwa)
3. [create-react-server](https://github.com/kirill-konshin/create-react-server)
4. [ssr-create-react-app](https://github.com/ayroblu/ssr-create-react-app)

### 3. Server Side Templating

This is yet another approach that I only ever saw in [this SO answer](https://stackoverflow.com/a/38129612). SST takes the middle ground between Static Serving and SSR.

Instead of serving files _as is_, modify the contents on the server, so embedding the data required for initial render.

## A wholesome approach

Here's my approach on coming up with a solution for CRA+SSR. The process is a bit long, but it's a one time investment that pays well in the long run.

### Workbench

Let's setup our workbench first. We'll create a project `my-app` which has a client and a server part. The client part is a CRA app `my-app-client` and the server is a basic [_express_](https://expressjs.com/) app.

```sh
npm i -g create-react-app express-generator

mkdir my-app
cd my-app

# create CRA app "my-app--client" in folder client/
create-react-app my-app--client --use-npm
mv my-app--client client

# test client
cd client
PORT=3000 npm start

# create express app "my-app--server" in folder server/
express --git my-app--server
mv my-app--server server

# test server
cd server
npm i
PORT=8000 npm start
```

We will connect our client's build directory to our server app. Create a file `server/paths.js` to store the paths used in our server code. In `server/app.js`, connect both the `BUILD_DIR` and `PUBLIC_DIR` as static folders.

```js
// server/paths.js

var path = require('path')

var BUILD_DIR = path.join(__dirname, '..', 'client', 'build')
var PUBLIC_DIR = path.join(__dirname, 'public')

module.exports = {
  BUILD_DIR,
  PUBLIC_DIR,
}

// server/app.js

var createError = require('http-errors')
var express = require('express')
var path = require('path')
var cookieParser = require('cookie-parser')
var logger = require('morgan')
var { BUILD_DIR, PUBLIC_DIR } = require('./paths')

...

app.use(logger('dev'))
app.use(express.json())
app.use(express.urlencoded({ extended: false }))
app.use(cookieParser())
app.use(express.static(BUILD_DIR))
app.use(express.static(PUBLIC_DIR))
```

By doing this, our express app will look for `index.html` first in the build folder of our client part and if it finds one, it will serve it. We can now build our react app and it will show up in the browser when we visit [http://localhost:3000](http://localhost:3000/).

**_Note_: We have just implemented** [_Static Serving_](#1-staticserving)_._

```js
# client/
npm run build

# server/
npm start
```

### Render React on Server

The next step is to wire our server app to first render the react app and then serve it. This will take some time since there are a number of steps involved.

First off, we have to add a _render hook in_ our html template for the server to render the app. Since our server code is not run inside a browser, it cannot find a render target using `document.getElementById('root')`.

```js
// client/public/index.html
...

<body>
  <noscript>
    You need to enable JavaScript to run this app.
  </noscript>
  <div id="root">__ROOT__</div>
```

Then we move on to the server part. Create a new file `react-renderer.js` that will handle the app render and add it in `app.js`.

```js
// server/react-renderer.js

var fs = require('fs')
var path = require('path')

var React = require('react')
var { renderToString } = require('react-dom/server')

var { BUILD_DIR } = require('./paths')
var App = require('../client/src/App')

function reactRenderer(req, res) {
  var app = renderToString(React.createElement(App))

  var html = fs
    .readFileSync(path.join(BUILD_DIR, 'index.html'), 'utf8')
    .replace('__ROOT__', app)

  return res.send(html)
}

module.exports = reactRenderer
```

We add this react-renderer function as the main route handler before we add any static directory. This ensures that our response is the rendered react app and not the static file that we built earlier.

```js
// server/app.js

var { BUILD_DIR, PUBLIC_DIR } = require('./paths')
var reactRenderer = require('./react-renderer')

...

app.use(logger('dev'))
app.use(express.json())
app.use(express.urlencoded({ extended: false }))
app.use(cookieParser())

app.get('/', reactRenderer)

app.use(express.static(BUILD_DIR))
app.use(express.static(PUBLIC_DIR))
```

Since we are now using react in our server code, we need to install it as well.

```sh
npm i react react-dom
```

In theory, this should work; in practice, it doesn't. When we start the server, we are greeted with this error message.

```sh
npm start

> my-app--server@0.0.0 start /my-app/server
> node ./bin/www

/my-app/client/src/App.js:1
(function (exports, require, module, __filename, __dirname)
{ import React, { Component } from 'react';
  ^^^^^^

SyntaxError: Unexpected token import
```

We **cannot** mix code written in ES6 and [CJS](https://en.wikipedia.org/wiki/CommonJS) standards. This means we need to convert our code in `client/` to CJS standard.

If we use `babel-register` to run our cross-standard code (which we won't), we would've implemented the [_babel-register_](#2-babel-register) approach. Instead, we are going to convert our entire codebase - client and server - to CJS.

### Migrating server code

First we'll deal with the server code. It's should be no surprise that we need [babel](https://babeljs.io/) to transform our code. And for that, we need to move our code ...

```sh
mkdir src/

mv routes src/
mv views src/
mv app.js src/
mv paths.js src/
mv react-renderer.js src/
```

... install required babel packages...

```sh
npm i\
  @babel/core\
  @babel/cli\
  @babel/preset-env\
  @babel/preset-react
```

... add babel config ...

```json
// server/package.json

{
  ...

  "scripts": {
    "lib": "rm -rf lib/ && babel src/ -d lib/",
    "start": "npm run lib && node ./bin/www"
  }

  ...

  "babel": {
    "presets": [
      "@babel/env",
      "@babel/react"
    ]
  }
}
```

... and make import path modifications in some files.

```js
// server/bin/www

var app = require('../lib/app')

// server/src/paths.js

var BUILD_DIR = path.join(__dirname, '..', '..', 'client', 'build')
var PUBLIC_DIR = path.join(__dirname, '..', 'public')

// server/src/react-renderer.js

var App = require('../../client/src/App')
```

### Migrating client code

Just as with server migration, we will use babel to transform our code.

In addition to that, we must also transform the imports separately. This is because the babel preset `babel-preset-react-app` disables module transform ([see here](https://github.com/facebook/create-react-app/blob/50607682ef1c5e28c158a613051ddafb30567b72/packages/babel-preset-react-app/dependencies.js#L78)). As a result, the code retains its `import/export` statements even after undergoing other babel transformations.

One more thing. Babel adds a number of "helper" packages into the code that it needs during runtime. For reasons unknown to me, babel is adding ES6 versions of those &amp; not CJ version. The only way I fix it is by recursively running regex replacements on the transformed code.

First, install required babel packages...

```sh
npm i @babel/cli @babel/plugin-transform-modules-commonjs
```

... add babel config and npm script ...

```json
// client/package.json

{
  ...
  "scripts": {
    "start": "react-scripts start",
    "build": "react-scripts build && npm run lib",

    "lib": "rm -rf lib/ && NODE_ENV=production babel src/ -d lib/ && npm run lib:esm",

    "lib:esm": "find lib/ -type f -name *.js -exec sed -i'' -e 's|@babel/runtime/helpers/esm|@babel/runtime/helpers|g' {} +",
    "test": "react-scripts test",
    "eject": "react-scripts eject"
  },
  ...
  "babel": {
    "plugins": [
      "@babel/plugin-transform-modules-commonjs"
    ],
    "presets": [
      "react-app"
    ]
  }
}
```

... and make import path modifications in some files.

```js
// server/src/react-renderer.js

...

var App = require('../../client/lib/App').default

function reactRenderer(req, res) {
  var app = renderToString(<App />)

  ...
}

module.exports = reactRenderer
```

Yet again, our setup is, in theory, complete. We can build our client code ...

```sh

npm run build

...

> my-app--client@0.1.0 lib /my-app/client
```

... and our server code as well ...

```sh

npm run lib

> my-app--server@0.0.0 lib /my-app/server

Successfully compiled 5 files with Babel.
```

... but starting our server still errors out. What gives?

```log
module.js:549
    throw err;
    ^

Error: Cannot find module './logo.svg'
```

Turns out that simple babel transformations require different setup for different types of imports. There are a few ways that I can think of to solve this issue. But this post has been going on for a while, so I will commenting out the pesky bits.

```js
// client/src/App.js

import React, { Component } from 'react'
// import logo from './logo.svg'
// import './App.css'

class App extends Component {
  render() {
    return (
      <div className='App'>
        <header className='App-header'>
          {/*<img src={logo} className="App-logo" alt="logo" />*/}
          <p>
            Edit <code>src/App.js</code> and save to reload.
          </p>
          <a
            className='App-link'
            href='https://reactjs.org'
            target='_blank'
            rel='noopener noreferrer'
          >
            Learn React
          </a>
        </header>
      </div>
    )
  }
}

export default App
```
